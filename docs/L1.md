# L1 Design: FileLayer + BlocksInFile

This document captures design decisions for the L1 phase. Unlike previous phases, this is not a mock — `FileOnDisk` is the real L1 implementation and `BlocksInFile` is the real L2.

---

## Overview

L1 abstracts away a file. It wraps OS file I/O and provides:
- File creation and opening
- Random-access reads and writes
- Process-level file locking
- Header awareness — L1 understands the SFS header format (magic + length-prefixed chunks) and knows where block data starts

L2 gains a new implementation, `BlocksInFile`, which stores and retrieves blocks within a single file managed by L1, replacing the mock `BlocksFromFiles` (which stored each block as a numbered file on disk).

---

## FileLayer Trait

**File:** `stream_fs/src/file_layer.rs`

The `FileLayer` trait is the L1 contract for L2. Like all layer traits, it uses `&self` with interior mutability for thread safety.

```rust
pub trait FileLayer: Send + Sync {
    /// Create a new SFS file at the given path.
    ///
    /// `upper_layers` contains the accumulated header sections from L2+L3+L4
    /// (possibly with placeholder values — correct sizes, uninitialised data).
    ///
    /// L1 writes: magic + L1 section + upper_layers to the file, then acquires
    /// an exclusive process lock. After this call, `data_offset()` returns the
    /// byte offset where block data begins.
    fn create(path: &str, upper_layers: &[u8]) -> Result<Self, SfsError>
    where
        Self: Sized;

    /// Open an existing SFS file at the given path.
    ///
    /// L1 reads the magic, validates the header format version, reads all
    /// length-prefixed header sections, pops its own (L1) section, validates
    /// it, and caches the remainder for `load_header()`.
    ///
    /// Acquires an exclusive process lock.
    fn open(path: &str) -> Result<Self, SfsError>
    where
        Self: Sized;

    /// Byte offset in the file where upper layer header data begins
    /// (immediately after magic + L1 section).
    ///
    /// L2 uses this to know where its header section lives in the file,
    /// enabling efficient in-place updates of bookkeeping fields.
    fn upper_layers_offset(&self) -> u64;

    /// Byte offset in the file where block data begins
    /// (immediately after ALL header sections).
    ///
    /// This value is fixed at create time and never changes.
    fn data_offset(&self) -> u64;

    /// Read bytes at the given absolute file offset.
    fn read(&self, offset: u64, buf: &mut [u8]) -> Result<usize, SfsError>;

    /// Write bytes at the given absolute file offset.
    fn write(&self, offset: u64, data: &[u8]) -> Result<(), SfsError>;

    /// Get current file length in bytes.
    fn len(&self) -> Result<u64, SfsError>;

    /// Set file length. Used to grow the file when allocating new blocks.
    fn set_len(&self, len: u64) -> Result<(), SfsError>;

    /// Flush all writes to disk.
    fn flush(&self) -> Result<(), SfsError>;

    /// Rewrite the upper layer header sections.
    ///
    /// L1 rewrites: magic + L1 section + upper_layers.
    /// `upper_layers.len()` must equal the original length (section sizes are
    /// fixed at create time — only values within sections change).
    fn store_header(&self, upper_layers: &[u8]) -> Result<(), SfsError>;

    /// Read and return the upper layer header sections
    /// (everything after magic + L1 section).
    fn load_header(&self) -> Result<Vec<u8>, SfsError>;
}
```

### Design notes

1. **`read`/`write` use absolute file offsets.** L2 computes `data_offset + block_id * block_size + offset_within_block`. L1 doesn't hide this calculation.

2. **`upper_layers_offset()`** lets L2 efficiently update its own header fields (e.g. `free_list_head`, `total_blocks`) without cascading through the full `store_header` chain.

3. **`data_offset()` is immutable** — fixed at create time, never changes. This is guaranteed because header section sizes are fixed.

## FileOnDisk Implementation

**File:** `stream_fs/src/file_on_disk.rs`

`FileOnDisk` wraps `std::fs::File` in a `Mutex` for thread-safe random-access I/O.

```rust
pub struct FileOnDisk {
    file: Mutex<std::fs::File>,
    upper_layers_offset: u64,
    data_offset: u64,
}
```

### Process-level locking

L1 acquires an exclusive OS file lock on create/open. The lock is held for the lifetime of the `FileOnDisk` instance and released on drop.

- **Windows:** `LockFileEx` with `LOCKFILE_EXCLUSIVE_LOCK | LOCKFILE_FAIL_IMMEDIATELY`
- **Unix:** `flock` with `LOCK_EX | LOCK_NB`

If the lock cannot be acquired, `create`/`open` returns an error: "SFS file is locked by another process".

Future work: shared (read-only) locks for concurrent readers across processes.

### Read/write implementation

All I/O goes through the `Mutex<File>`. Each `read`/`write` call:
1. Locks the mutex
2. Seeks to the requested offset
3. Performs the read/write
4. Drops the lock

### L1 header section

Format: `| length: u16 | "ondisk" | version: u8 |`

- Length: 9 (2 + 6 + 1)
- Identifier: `"ondisk"` (6 bytes)
- Version: 0

The header/data boundary (`data_offset`) is stored in the magic section as `total_header_length`, not in the L1 section. This is a file-format concern, not an L1 concern — any code can read the 12-byte magic to find where block data starts without parsing layer sections.

## Header Chain with L1

### On-disk header format

```
Offset 0:   Magic "stream_fs" (9) + version (1) + total_header_length (2) = 12 bytes
Offset 12:  L1 section: | 9u16 | "ondisk" | 0u8 |                         =  9 bytes
Offset 21:  L2 section: | 27u16 | "blocks" | 0u8 | bss | biw |
                         total_blocks(u64) | free_list_head(u64) |         = 27 bytes
Offset 48:  L3 section: | 25u16 | "pyra  " | 0u8 | streams_desc (16B) |   = 25 bytes
Offset 73:  L4 section: | 17u16 | "filing" | 0u8 | root_dir_stream_id |   = 17 bytes
Offset 90:  ---- data_offset: block data begins here ----
```

**Total header: 90 bytes** (with `BlocksInFile` L2). Block 0 starts at offset 90.

The `total_header_length` field in the magic section is `u16` (max 64 KB of headers). If this ever proves insufficient, bump `header_format_version` to 1 and use `u32`.

Note: With `BlocksFromFiles` (L2 mock), the L2 section is only 11 bytes (no `total_blocks`/`free_list_head`), so the total differs. But this doesn't matter because `BlocksFromFiles` doesn't use `data_offset` — it stores blocks as separate files.

### Create flow (two-pass initialisation)

```
Pass 1 — headers flow down (create calls, going down the stack):

  L4 (Sfs::create):
    Build L4 placeholder section: | 17u16 | "filing" | 0u8 | 0u64 |
    Call L3::create(path, biw, bss, l4_placeholder)

  L3 (StreamsFromBlocks::create):
    Build L3 placeholder section: | 25u16 | "pyra  " | 0u8 | 0u64 0u64 |
    Prepend to upper_layers → 25 + 17 = 42 bytes
    Call L2::create(path, bss, biw, combined)

  L2 (BlocksInFile::create):
    Build L2 section: | 27u16 | "blocks" | 0u8 | bss | biw | 0u64 | sentinel |
    Prepend to upper_layers → 27 + 42 = 69 bytes
    Call L1::create(path, combined)

  L1 (FileOnDisk::create):
    total_header_length = 12 + 9 + 69 = 90
    Write: magic(12, includes total_header_length) + L1_section(9) + upper_layers(69) = 90 bytes
    data_offset = total_header_length = 90
    Acquire exclusive file lock
    Return L1 instance

Pass 2 — layers initialise (returning up the stack):

  L2 returns:
    Knows data_offset = 96 from L1
    Initialises: total_blocks=0, free_list_head=sentinel
    Ready for block allocation

  L3 returns:
    Has L2 ready for block allocation
    Streams descriptor: size=0, top_block=0 (no blocks allocated yet)
    Rewrites L3 header with real descriptor via store_header

  L4 returns:
    Has L3 ready
    Calls create_stream() → allocates root directory stream (blocks allocated in L2)
    Rewrites L4 header with real root_dir_stream_id via store_header
```

### Open flow

```
  L1 (FileOnDisk::open):
    Read file, acquire exclusive lock
    Verify magic: "stream_fs" + version 0 + total_header_length
    data_offset = total_header_length
    Read L1 section, verify identifier "ondisk"
    Read exactly (data_offset - upper_layers_offset) bytes as upper_layers
    Return L1 instance

  L2 (BlocksInFile::open):
    Call L1::open(path) → get L1 instance
    Call L1::load_header() → get upper_layers (L2+L3+L4 sections)
    Parse L2 section: identifier "blocks", bss, biw, total_blocks, free_list_head
    Cache remainder (L3+L4 sections)
    Return L2 instance

  L3 (StreamsFromBlocks::open):
    Call L2::open(path) → get L2 instance
    Call L2::load_header() → get L3+L4 sections
    Parse L3 section: identifier "pyra  ", streams_desc
    Cache L4 section
    Return L3 instance

  L4 (Sfs::open):
    Call L3::open(path) → get L3 instance
    Call L3::load_header() → get L4 section
    Parse L4 section: identifier "filing", root_dir_stream_id
    Return Sfs instance
```

## BlocksInFile — New L2 Implementation

**File:** `stream_fs/src/blocks_in_file.rs`

`BlocksInFile<L1: FileLayer>` implements `BlockLayer`, storing all blocks within a single file managed by L1.

```rust
pub struct BlocksInFile<L1: FileLayer> {
    file: L1,
    block_size_shift: u8,
    block_index_width: u8,
    state: Mutex<BlocksInFileState>,
    /// Cached file offset where L2's header section starts (for in-place updates)
    l2_section_offset: u64,
}

struct BlocksInFileState {
    total_blocks: u64,
    free_list_head: u64,
}
```

### Block layout

Block `n` is stored at file offset: `data_offset + n * block_size`

All blocks are `block_size` bytes. New blocks are zeroed on allocation.

### L2 header section

Format: `| length: u16 | "blocks" | version: u8 | block_size_shift: u8 | block_index_width: u8 | total_blocks: u64 | free_list_head: u64 |`

- Length: 27 (2 + 6 + 1 + 1 + 1 + 8 + 8)
- Identifier: `"blocks"` (the real L2, distinguishing from `"blkfil"` mock)
- `total_blocks`: number of blocks in the file (block IDs are `0..total_blocks`)
- `free_list_head`: block ID of first free block, or sentinel for "none free"

### Efficient bookkeeping updates

On every `allocate_block` / `deallocate_block`, L2 needs to update `total_blocks` and/or `free_list_head`. Rather than cascading through the full `store_header` chain, L2 writes these fields directly to the file at known offsets:

```
l2_section_offset = file.upper_layers_offset()

total_blocks is at:     l2_section_offset + 11  (after length + id + ver + bss + biw)
free_list_head is at:   l2_section_offset + 19  (after total_blocks)
```

This is O(1) — just 8 bytes written at a known offset.

### Index overflow protection

Same as `BlocksFromFiles`: the sentinel value (all 0xFF in `block_index_width` bytes) is reserved and must never be allocated. `allocate_block` checks `block_id < sentinel`.

## Free List

The free list is a singly-linked list stored within the blocks themselves, as specified in the architecture (Section "Reusing blocks").

### Structure

- `free_list_head` in L2's header section: block ID of first free block, or `sentinel` for "empty list"
- Each free block: first `block_index_width` bytes = next free block ID (or `sentinel` for end of list)
- The remaining bytes of a free block are undefined

### Allocate block

```
1. Lock state mutex
2. If free_list_head != sentinel:
   a. block_id = free_list_head
   b. Read first block_index_width bytes of block → next_free
   c. free_list_head = next_free
   d. Zero the entire block
   e. Persist free_list_head to header
   f. Return block_id
3. Else (no free blocks):
   a. block_id = total_blocks
   b. Check block_id < sentinel (overflow protection)
   c. Extend file by block_size bytes (set_len)
   d. Zero the new block
   e. total_blocks += 1
   f. Persist total_blocks to header
   g. Return block_id
```

### Deallocate block

```
1. Lock state mutex
2. Write free_list_head (as block_index_width bytes LE) into first bytes of block
3. free_list_head = block_id
4. Persist free_list_head to header
```

### Thread safety

All free list operations are protected by the `state` mutex. Block I/O (reads/writes at known offsets) goes through L1, which has its own internal mutex.

## Process-Level Locking

### Current phase (exclusive only)

For simplicity, all opens are exclusive (read-write). Only one process can access an SFS file at a time.

- `create`: creates file + exclusive lock
- `open`: opens file + exclusive lock
- Lock is released when `FileOnDisk` is dropped

If a lock cannot be acquired (another process holds it), the operation fails immediately with an error.

### Future phase (shared/exclusive)

The architecture specifies (Section "SFS file thread, process, machine & crash safety"):
- Multiple processes can open for reading simultaneously (shared lock)
- A single process can open for writing (exclusive lock)

This will require a mode parameter on `open` and is deferred to a future phase.

## Trait Signature Changes

### `BlockLayer::create`

```rust
// Before:
fn create(path: &str, block_size_shift: u8, block_index_width: u8) -> Result<Self, SfsError>;

// After:
fn create(path: &str, block_size_shift: u8, block_index_width: u8, upper_layers: &[u8]) -> Result<Self, SfsError>;
```

`upper_layers` contains the accumulated L3+L4 header sections (possibly with placeholder values).

**Impact:**
- `BlocksFromFiles::create` — receives upper_layers, writes full header (magic + L2 section + upper_layers) to the header file during create. Currently header is written later via `store_header`; this just moves it earlier.
- `BlocksInFile::create` — prepends L2 section to upper_layers, passes to L1::create. Gets back L1 with known data_offset.

### `StreamLayer::create`

```rust
// Before:
fn create(path: &str, block_index_width: u8, block_size_shift: u8) -> Result<Self, SfsError>;

// After:
fn create(path: &str, block_index_width: u8, block_size_shift: u8, upper_layers: &[u8]) -> Result<Self, SfsError>;
```

**Impact:**
- `StreamsFromFiles::create` — receives upper_layers, writes header during create (same effect as current `store_header` call).
- `StreamsFromBlocks::create` — builds L3 placeholder section, prepends to upper_layers, passes to L2::create.

### `Sfs::create`

```rust
// Before:
pub fn create(path: &str, block_index_width: u8, block_size_shift: u8) -> Result<Self, SfsError>;

// After (no change to public API):
pub fn create(path: &str, block_index_width: u8, block_size_shift: u8) -> Result<Self, SfsError>;
```

Internally, L4 builds its placeholder section and passes it to L3::create. The public API doesn't change.

### No changes to C ABI or Python bindings

The `sfs_create` C function and Python `Sfs.create` signatures are unchanged. The header passing is entirely internal.

## Open Questions

1. **Endianness tracking**: The architecture specifies SFS tracks file endianness. The current implementation is little-endian only. Should L1's header include an endianness marker? Deferred for now — all platforms we target are little-endian.

## Resolved Questions

1. **`store_header` size validation**: L1 enforces that `store_header(upper_layers)` has exactly the same length as the original, returning an error on mismatch. Header section sizes are fixed at create time — only values within sections change.

2. **File extension**: Both single-file (`BlocksInFile`) and directory-based (`BlocksFromFiles`) backends use `.sfs`. The mock backends are debugging tools; the file/directory distinction is transparent to the caller.

## Decision Log

| # | Decision | Rationale |
|---|----------|-----------|
| 1 | **L1 is header-aware** | L1 reads the magic + header format version, chunks length-prefixed sections, pops its own, and passes the rest up. This lets L1 know exactly where block data starts (`data_offset`). |
| 2 | **Two-pass create** | Each layer passes its header section (correct size, possibly placeholder values) down during create. L1 writes them all. Returning up, each layer initialises and rewrites its header with real values. This ensures `data_offset` is known before the first block allocation. |
| 3 | **Blocks start immediately after the header** | No padding, no wasted space. `data_offset = total_header_size`. Block `n` at offset `data_offset + n * block_size`. |
| 4 | **Free list in block content** | Freed blocks store the next-free pointer in their first `block_index_width` bytes, forming a singly-linked list. `free_list_head` in L2's header section. Architecture-specified design (Section "Reusing blocks"). |
| 5 | **Exclusive process locking (for now)** | All opens are exclusive. Shared (read-only) locks deferred to a future phase. |
| 6 | **`upper_layers` added to `create` signatures** | `BlockLayer::create` and `StreamLayer::create` gain an `upper_layers: &[u8]` parameter. This enables the two-pass create flow without L1 needing to guess header sizes. |
| 7 | **L1 identifier: `"ondisk"`** | Distinguishes the real file-backed L1 from potential future implementations (e.g. in-memory). |
| 8 | **L2 identifier: `"blocks"`** | Distinguishes the real single-file L2 from the mock `"blkfil"`. |
| 9 | **Efficient in-place header updates** | L2 writes `total_blocks` and `free_list_head` directly to known file offsets rather than cascading through `store_header`. Only the full `store_header` chain is used for L3/L4 updates. |
| 10 | **`FileOnDisk` uses `Mutex<File>`** | Portable approach — lock the file handle, seek, read/write. Avoids platform-specific `pread`/`pwrite` APIs. |
| 11 | **`total_header_length` in magic section** | The header/data boundary is a file-format concern, not an L1 concern. Storing `total_header_length` (= `data_offset`) in the magic section lets any code find where block data starts by reading just the 12-byte magic, without parsing layer sections. Previously this was stored as `data_offset` in the L1 section. |
